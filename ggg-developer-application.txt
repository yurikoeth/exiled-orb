APPLICATION TYPE
----------------------------------------------------------------
Native desktop application (Windows; built with Tauri v2 — Rust + WebView).
Single-user, runs locally on the user's machine. No backend server, no shared
infrastructure, no multi-user accounts. Each user runs their own copy with
their own credentials.

----------------------------------------------------------------
DESCRIPTION
----------------------------------------------------------------
ExiledOrb is a personal desktop overlay companion for Path of Exile 1 and
Path of Exile 2. It runs alongside the game and helps with everyday tasks:

- Reads the local Client.txt log to track current zone, area level,
  character level-ups, and deaths in the active session.
- Reads item text from the system clipboard (when the user presses Ctrl+C
  on an item in-game) and looks up indicative prices on poe.ninja.
- Provides offline reference data: act-by-act leveling guide, atlas
  strategies, dangerous map mod warnings, and tier-evaluation for rare
  item rolls.
- Optional AI build advice using the user's own Anthropic API key — the
  user pastes their own key, the app makes calls directly from their
  machine to Anthropic. We don't proxy or store anything on a server.

The tool is read-only with respect to the game. It does not automate
gameplay, does not perform trades, does not interact with the game client
beyond observing Client.txt and the system clipboard, and does not modify
game files.

----------------------------------------------------------------
WHY OAUTH IS NEEDED
----------------------------------------------------------------
The legacy public character-window endpoint
(https://www.pathofexile.com/character-window/get-characters) returns only
PoE1 characters. We've verified that the `realm=poe2` query parameter is
silently ignored on this endpoint, and that public profile pages at
/account/view-profile return 403 to unauthenticated requests.

For the PoE2 half of the app to do anything useful with character data
(show the user their own characters, display equipped gear, run AI build
analysis on their own builds), we need authenticated access through the
official OAuth2 API at api.pathofexile.com.

The flow we intend to use is the standard Authorization Code + PKCE flow
for native apps:
  1. User clicks "Connect with GGG" inside the desktop app.
  2. App opens the system browser to /oauth/authorize.
  3. User signs in on pathofexile.com and approves the requested scopes.
  4. GGG redirects to http://localhost:<ephemeral port>/callback with a code.
  5. App exchanges the code for an access token + refresh token.
  6. Tokens are stored locally on the user's machine (tauri-plugin-store,
     encrypted at rest via Windows DPAPI).
  7. Refresh token is used silently when the access token expires.

----------------------------------------------------------------
REDIRECT URI
----------------------------------------------------------------
http://localhost/callback
(With an ephemeral port chosen at runtime — exact form depends on what
your registration system accepts. We can also use a fixed port like
http://localhost:11343/callback if required.)

----------------------------------------------------------------
SCOPES REQUESTED
----------------------------------------------------------------
account:characters    — list the user's characters across realms
account:profile       — read basic profile (account name, primary realm)

We do NOT need and will NOT request:
  - account:stashes (no stash management features)
  - account:leagues (no private league features)
  - account:item_filter:write (read-only tool)
  - any trade-related scopes

If a finer-grained read-only character scope exists (e.g. "characters:read"),
we'd prefer that. Whatever the minimum scope is to read the user's own
characters and their equipped items.

----------------------------------------------------------------
RATE LIMIT BEHAVIOR
----------------------------------------------------------------
- We honor the X-Rate-Limit-* response headers and back off accordingly.
- Character list refresh is user-triggered (button click) — not automatic
  polling.
- Equipped-item fetch is on-demand when the user expands a specific
  character.
- Already-fetched data is cached in memory for the session; we don't
  re-fetch on every render.
