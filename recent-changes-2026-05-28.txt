RECENT CHANGES — 2026-05-28 OAUTH PREP PASS

Triggered by GGG's email approving the developer-app OAuth credentials,

1. GGG de-risk — forbidden endpoints disabled
---------------------------------------------
Two Rust Tauri commands now return an explanatory error instead of
calling the legacy `character-window/*` endpoints:

  - `fetch_characters` (apps/overlay/src-tauri/src/oauth.rs)
      Was: GET https://www.pathofexile.com/character-window/get-characters
      Now: Err("GGG character list is disabled — the legacy
                character-window endpoint is a TOS breach (per GGG email
                2026-05-28). PoE2 characters remain available via the
                Live Session tile and log-mined history below. Full GGG
                character list will return once the OAuth integration
                is finished.")

  - `fetch_character_items` (same file)
      Was: GET https://www.pathofexile.com/character-window/get-items
      Now: similar Err with a "use Capture Gear" hint for PoE2.

  Net effect: zero HTTP traffic to the forbidden endpoints from
  yurikoeth#5030's machine. The frontend invokes still fire; the error
  surfaces in the existing red error banner in GggAccount.tsx.

  What this breaks (documented in oauth-migration-affected-features.txt):
    - PoE1 character list (witchtimee, ironmaidenn) — section is empty
    - PoE1 character gear viewer (row expansion shows the error)
    - "Set as Active Build" from a GGG row (depends on items)
    - "Analyze Build" from a GGG row (same)
    - "Refresh Gear" button (same)

  What still works (no degradation):
    - Live Session tile for the active PoE2 character
    - Gear Capture flow (clipboard streaming)
    - Character history mining (local Client.txt only)
    - AI build review for PoE2 (uses captured gear)
    - Clipboard price check via poe.ninja (third-party, not GGG)
    - Market tab, Client.txt watcher, speedrun tools, leveling guide
