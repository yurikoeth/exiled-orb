FEATURES AFFECTED BY OAUTH MIGRATION + 2026-05-28 PRUNING PASS
==============================================================

Use this as the rebuild checklist when the GGG OAuth integration is finished
(and when we decide to bring back any pruned features).


SECTION A — TEMPORARILY DISABLED until OAuth lands
---------------------------------------------------
These features depend on the legacy `character-window/get-characters` and
`character-window/get-items` endpoints. As of 2026-05-28 GGG explicitly
named those as a TOS breach, so the Rust commands now short-circuit with
an explanatory error. The UI code is unchanged — just the backend says no.

  1. PoE1 character list (Characters tab)
     - Previously fetched: witchtimee (Elementalist, lvl 76),
       ironmaidenn (Witch, lvl 1) via fetch_characters.
     - Current state: PATH OF EXILE 1 section is empty / shows an error
       banner. Live Session tile + PoE2 log-mined chars still render.

  2. PoE1 character gear viewer
     - Previously fetched via fetch_character_items when expanding a row.
     - Current state: row expansion shows the error from the disabled
       Tauri command.

  3. "Set as Active Build" from a GGG character row
     - The button on each GggCharacter row would call setAsActiveBuild,
       which preloaded items via fetch_character_items before saving.
     - Current state: button still renders if rows are rendered, but
       fetch fails. (For PoE2 the equivalent flow on the Live Session
       tile still works — Capture gear → Save Build.)

  4. "Analyze Build" from a GGG character row
     - Same dependency chain: needs items, which now error.
     - Current state: For PoE2 the Analyze build button on the Live
       Session tile still works (uses captured gear).

  5. "Refresh Gear" button on expanded char row
     - Calls loadItems(name, force=true), which calls fetch_character_items.
     - Current state: errors. Capture gear is the workaround for PoE2.


REBUILD PLAN for section A (once OAuth ships):
  - Replace `fetch_characters` body with: GET api.pathofexile.com/character
    with `Authorization: Bearer <access_token>`. Response now actually
    includes PoE2 characters too (the original reason we wanted OAuth).
  - Replace `fetch_character_items` body with: GET api.pathofexile.com/
    character/<name> with the same Bearer header. Returns equipped items
    in a slightly different schema — re-verify the field mapping
    (inventoryId / sockets / explicitMods → BuildItem).
  - Remove the temporary error messages.
  - Optional: hide the Live Session "Capture gear" button for GGG-fetched
    characters since live gear loading would be authoritative. Keep
    Capture as a fallback for unauthenticated users.
